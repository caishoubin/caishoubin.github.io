Storage constants

A standard Storage Container has 24 slots. An Industrial Storage Container has 48 slots. Multiply usable slots by the stack size of your particular item. Source: Storage Container. Industrial storage does not guarantee equal flow through two output connections.

Transport formulas

Parallel belts = ceil(target flow / belt capacity)
Single-belt load = target flow / belt capacity × 100%
Sustainable route flow = min(available supply, belt capacity)
Delivered flow = min(demand, sustainable route flow)
Unmet demand = max(0, demand − sustainable route flow)
Sized-parallel capacity = parallel belts × selected belt capacity
Sized-parallel delivery = min(supply, demand, sized-parallel capacity)

Parallel sizing uses “target transported flow.” The bottleneck check separately uses available supply and consumer demand on one selected-capacity route. The separately labeled parallel scenario shows what those independent routes could deliver, with the same total supply and demand. It does not assume a shared slower input or output magically gains capacity. The tier comparison shows each tier’s route count for the target and its single-route delivery for the entered supply/demand. The lowest sufficient tier is a capacity recommendation only, not a cost, unlock or layout recommendation.

Buffer formulas

Net rate = actual input − required output
Time to empty = stock / (output − input), when output > input
Time to full = (capacity − stock) / (input − output), when input > output
Outage coverage = stock / output
Required outage stock = ceil(output × outage minutes)
Time to reserve = max(0, required stock − current stock) / net surplus
Post-outage stock = max(0, current stock − output × outage minutes)
Recovery to pre-outage stock = (current stock − post-outage stock) / net surplus

At equal input and output, inventory does not change in this model. At zero output, outage coverage is unlimited because no items are consumed. A zero-duration outage requires zero stock. Inputs must be zero or from 0.000001 to 1,000,000,000; belt and storage capacities must be nonzero. Blank fields, non-numbers and non-finite values are rejected. Current stock cannot exceed maximum storage. Outage reserves above JavaScript’s exact whole-number range (9,007,199,254,740,991 items) are rejected rather than presented with false precision. Outage stock and route counts are rounded up, with a small correction for binary floating-point noise at whole-number boundaries. Outage stock is a whole-item planning reserve. Displayed values may be rounded to two decimal places.

Refill times require positive net input unless the target is already reached. A reserve that exceeds capacity is marked unreachable. Recovery restores the stock actually consumed, not a completely full container and not missed production. If stock runs out during an outage, unserved demand is shown separately. Readiness for a second outage starts from post-outage stock and targets the full required reserve. These times exclude machine restart delays.

Scope and limits

  • Solid items only. No fluid dynamics, train scheduling, power simulation or recipe dataset.
  • Constant rates and continuously accessible stock. Machine cycles, travel time, priority routing and uneven outputs are not simulated.
  • Buffer input must be the actual rate after upstream bottlenecks. Its output assumes downstream conveyors can carry the entered rate.
  • Manifold startup can differ from steady-state behavior. See the Manifold reference.
  • A buffer delays a sustained shortage; it cannot create missing production.

Verification

The calculation model has automated checks for known examples, zero rates, equal rates, full and empty stock, invalid values, custom capacities, tier boundaries, parallel delivery, recharge calculations and numeric extremes. Versioned plans have validation and round-trip tests, and simulated-DOM checks cover saving, sharing, malformed links, clipboard failures and tab/preset interactions. Those checks verify arithmetic and validation; they do not substitute for a real factory test. No imported third-party recipe data or copyrighted game artwork is used.
